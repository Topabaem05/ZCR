# T18 · Windows 확장 — 선택 Implementation Plan

**Goal:** Windows 확장 — 선택를 독립 검증 가능한 모듈과 증거로 완성한다.  
**Architecture:** [SDD](../docs/02-SDD.md)와 [공개 인터페이스](../docs/17-Data-Model-and-Interfaces.md)를 준수한다.  
**Tech Stack:** Zig 0.16.0, 승인된 public OS API.  
**Spec:** [구현 로드맵](../docs/13-Implementation-Roadmap.md), [테스트 계획](../docs/12-Performance-and-Test-Plan.md).  
**Dependencies:** T17, T15  
**Status:** NOT_SELECTED — 현재 실행 증거와 미완료 게이트는 [상태표](INDEX.md) 및 [progress.json](progress.json)을 따른다.

## 파일 소유권

아래는 향후 runtime repository에서 생성·수정할 경로다. ZIP에 구현됐다는 뜻이 아니다.

- `src/platform/windows.zig`
- `src/watch/windows.zig`
- `src/broker/windows_pipe.zig`
- Test: `tests/t18_test.zig`
- Evidence: `evidence/T18/` (사용자 source와 다른 task 경로는 금지)

공유 `build.zig`, `src/core/types.zig`, schemas는 통합자 소유다. 이 Task가 그 파일 소유자인 T01이 아닌 경우 export/contract 변경은 handoff로 요청한다. dependency의 파일을 몰래 수정해서 test를 통과시키지 않는다.

## 소비·생산 계약

**Consumes:** common platform types; I14/I18.  
**Produces:** optional Windows capabilities; current-user named-pipe and reparse policy.  
**금지/주의:** Windows미구현이Apple/Linux출시를막지는않지만Windows지원표시와binary배포는금지한다.

## task-specific 구현 지침

UTF-8/UTF-16 변환, volume ID, reparse point, ADS, device path를 검사한다. no-replace와 open-file 상호작용을 실제 Windows에서 시험한다. EcoQoS는 기능 검사 뒤 background에만 선택 적용한다. 불가능한 capability는 명시적으로 비활성화한다.

## 검증 시나리오

| ID | Given | When | Then / 합격 조건 |
|---|---|---|---|
| WIN-GATE | Windows11 actual runner · reparse/pipe/rename fixtures | backend suite | 잘못된 path/peer 거부, atomic semantics와 capability 일치 |

첫 RED test는 다음 명시적 동작을 assertion으로 만든다. 이것은 구현자가 실행 시험으로 옮길 **test specification**이며 현재 실행한 결과가 아니다.

```json
{
  "id": "WIN-GATE",
  "given": "actual platform fixture",
  "when": "run platform gate",
  "then": "truthful capability and correct behavior"
}
```

## Step별 실행

- [ ] **S01 · scope preflight.** `task-t18` 전용 worktree에서 base/head와 dependency source/evidence hash를 고정한다. 허용 목록은 위 파일들+전용 tests/evidence뿐이다. dirty 사용자 변경이 있으면 보존하고 새 깨끗한 task worktree를 사용한다. source·build cache·TMP·test logs를 다른 task와 공유하지 않는다.
- [ ] **S02 · RED.** `tests/t18_test.zig`에 위 시나리오와 이 Task의 나머지 검증 행을 작성한다. 아래 명령을 실행하고 예상 기능이 없거나 올바른 assertion이 실패해서 RED인지 확인한다. unrelated compiler/toolchain 오류는 기능 RED 증거가 아니다.

```sh
zig build test -Dtest-group=security -Doptimize=Debug
```

- [ ] **S03 · 최소 구현.** task-specific 구현 지침의 순서로 소유 모듈만 구현한다. 필요한 type은 소비 계약에서 가져오고 공개 API 변경은 통합자에게 전달한다. skip/상수 성공값/에러 삼키기로 assertion을 통과시키지 않는다.
- [ ] **S04 · GREEN 및 실패 경로.** 동일 test를 재실행하고 정상·취소·예산·I/O failure를 시험한다. `WIN-GATE`와 표의 각 test에 source commit·binary SHA-256·command·exit code·stdout/stderr hash를 기록한다. 아직 없는 platform은 NOT_RUN으로 남긴다.
- [ ] **S05 · regression/scope.** 해당 group의 Debug/ReleaseSafe 시험과 dependencies의 영향받은 contract tests를 수행한다. tracked/untracked/rename/delete 경로가 소유 범위인지 검사한다. review 전에 memory lifetime과 error return을 다시 확인한다.
- [ ] **S06 · handoff.** `evidence/T18/handoff.json`에 base/head, contract digest, 변경 목록, export signature, test 결과, 제한·미통과 gate를 저장한다. 리뷰 가능한 전용 commit을 생성하되 통합자는 그 commit을 적용한 실제 integration binary로 다시 시험한다.

## 완료 게이트

전체 명시 test가 실행되어야 COMPLETE다. 경로 제한 위반, 요구 API와 다른 타입, lifecycle leak, 가짜 PASS, 실제 실행 없이 플랫폼 지원 표시는 REJECT다. 성능 실험이 포함되면 raw trace와 corpus/config digest를 남긴다. 다음 task는 말로 전달된 상태 대신 승인된 handoff를 읽고 시작한다.
