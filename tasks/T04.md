# T04 · 정확하고 제한된 범위 Read Implementation Plan

**Goal:** 정확하고 제한된 범위 Read를 독립 검증 가능한 모듈과 증거로 완성한다.  
**Architecture:** [SDD](../docs/02-SDD.md)와 [공개 인터페이스](../docs/17-Data-Model-and-Interfaces.md)를 준수한다.  
**Tech Stack:** Zig 0.16.0, 승인된 public OS API.  
**Spec:** [구현 로드맵](../docs/13-Implementation-Roadmap.md), [테스트 계획](../docs/12-Performance-and-Test-Plan.md).  
**Dependencies:** T02, T03  
**Status:** PLANNED — 구현·런타임 시험 미실행. 필수 Task.

## 파일 소유권

아래는 향후 runtime repository에서 생성·수정할 경로다. ZIP에 구현됐다는 뜻이 아니다.

- `src/fs/read.zig`
- `src/fs/metadata.zig`
- Test: `tests/t04_test.zig`
- Evidence: `evidence/T04/` (사용자 source와 다른 task 경로는 금지)

공유 `build.zig`, `src/core/types.zig`, schemas는 통합자 소유다. 이 Task가 그 파일 소유자인 T01이 아닌 경우 export/contract 변경은 handoff로 요청한다. dependency의 파일을 몰래 수정해서 test를 통과시키지 않는다.

## 소비·생산 계약

**Consumes:** I01 Capability; I02 Reservation; ReadSpec.  
**Produces:** readRange I03; FileVersion/whole-file digest behavior.  
**금지/주의:** rangehash를wholehash로반환하지않고live파일mmap은기본비활성이다.

## task-specific 구현 지침

regular file만 handle-relative로 열고 bounded read와 전후 metadata 확인을 수행한다. UTF-8, CRLF, 원본 bytes와 line offsets를 보존한다. write_intent 요청은 8 MiB 이하 파일의 전체 hash를 계산한다. 오류·취소 경로에서도 FD와 예약을 회수한다.

## 검증 시나리오

| ID | Given | When | Then / 합격 조건 |
|---|---|---|---|
| IO-001 | UTF-8 fixture bytes alpha\nbeta\n | read lines 1..2 | 두 줄과 원본 byte offsets가 정확하며 EOF phantom line 없음 |
| IO-002 | 빈 파일과 trailing newline 없는 파일 | 동일 범위 read | 빈 파일0줄, 비종결 마지막 줄1개, complete=true |
| IO-003 | BOM·CRLF·혼합 newline·한글 파일 | write_intent read | raw bytes와 SHA-256을 유지, normalization 없음 |
| IO-004 | 최대5000줄·매우 긴 한 줄·64KiB 파일 | 작은 output budget read | 명확한 truncation 또는 E_OUTPUT_BUDGET, buffer overflow 없음 |
| IO-005 | short read/EINTR/change-after-open 주입 | bounded read | 안전 재시도 또는 changed 오류, 다른 버전 snippet 결합 없음 |
| IO-006 | 8MiB 파일의 중간200줄 | write_intent=true/false 비교 | true는 전체hash, false는 whole hash null 허용; FD/arena 회수 |

첫 RED test는 다음 명시적 동작을 assertion으로 만든다. 이것은 구현자가 실행 시험으로 옮길 **test specification**이며 현재 실행한 결과가 아니다.

```json
{
  "id": "IO-001",
  "given": "UTF-8 fixture bytes alpha\\nbeta\\n",
  "when": "read lines 1..2",
  "then": "두 줄과 원본 byte offsets가 정확하며 EOF phantom line 없음"
}
```

## Step별 실행

- [ ] **S01 · scope preflight.** `task-t04` 전용 worktree에서 base/head와 dependency source/evidence hash를 고정한다. 허용 목록은 위 파일들+전용 tests/evidence뿐이다. dirty 사용자 변경이 있으면 보존하고 새 깨끗한 task worktree를 사용한다. source·build cache·TMP·test logs를 다른 task와 공유하지 않는다.
- [ ] **S02 · RED.** `tests/t04_test.zig`에 위 시나리오와 이 Task의 나머지 검증 행을 작성한다. 아래 명령을 실행하고 예상 기능이 없거나 올바른 assertion이 실패해서 RED인지 확인한다. unrelated compiler/toolchain 오류는 기능 RED 증거가 아니다.

```sh
zig build test -Dtest-group=io -Doptimize=Debug
```

- [ ] **S03 · 최소 구현.** task-specific 구현 지침의 순서로 소유 모듈만 구현한다. 필요한 type은 소비 계약에서 가져오고 공개 API 변경은 통합자에게 전달한다. skip/상수 성공값/에러 삼키기로 assertion을 통과시키지 않는다.
- [ ] **S04 · GREEN 및 실패 경로.** 동일 test를 재실행하고 정상·취소·예산·I/O failure를 시험한다. `IO-001`와 표의 각 test에 source commit·binary SHA-256·command·exit code·stdout/stderr hash를 기록한다. 아직 없는 platform은 NOT_RUN으로 남긴다.
- [ ] **S05 · regression/scope.** 해당 group의 Debug/ReleaseSafe 시험과 dependencies의 영향받은 contract tests를 수행한다. tracked/untracked/rename/delete 경로가 소유 범위인지 검사한다. review 전에 memory lifetime과 error return을 다시 확인한다.
- [ ] **S06 · handoff.** `evidence/T04/handoff.json`에 base/head, contract digest, 변경 목록, export signature, test 결과, 제한·미통과 gate를 저장한다. 리뷰 가능한 전용 commit을 생성하되 통합자는 그 commit을 적용한 실제 integration binary로 다시 시험한다.

## 완료 게이트

전체 명시 test가 실행되어야 COMPLETE다. 경로 제한 위반, 요구 API와 다른 타입, lifecycle leak, 가짜 PASS, 실제 실행 없이 플랫폼 지원 표시는 REJECT다. 성능 실험이 포함되면 raw trace와 corpus/config digest를 남긴다. 다음 task는 말로 전달된 상태 대신 승인된 handoff를 읽고 시작한다.
