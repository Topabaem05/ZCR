## task-specific 구현 지침

RAM profile과 OS pressure, thermal, low-power 신호를 합성한다. warning에서는 cache 목표를 절반으로, critical에서는 CPU 1 / I/O 1로 줄이고 bulk admission을 막는다. 정상 10초 뒤 5초마다 10%p씩 회복한다. 선택적 모델 보호는 5초 window 3회 연속 5% 저하일 때 동작한다.

## Step별 실행

- [ ] **S01 · scope preflight.** `task-t16` 전용 worktree에서 base/head와 dependency source/evidence hash를 고정한다. 허용 목록은 위 파일들+전용 tests/evidence뿐이다. dirty 사용자 변경이 있으면 보존하고 새 깨끗한 task worktree를 사용한다. source·build cache·TMP·test logs를 다른 task와 공유하지 않는다.
- [ ] **S02 · RED.** `tests/t16_test.zig`에 위 시나리오와 이 Task의 나머지 검증 행을 작성한다. 아래 명령을 실행하고 예상 기능이 없거나 올바른 assertion이 실패해서 RED인지 확인한다. unrelated compiler/toolchain 오류는 기능 RED 증거가 아니다.

```sh
zig build test -Dtest-group=scheduler -Doptimize=Debug
```

- [ ] **S03 · 최소 구현.** task-specific 구현 지침의 순서로 소유 모듈만 구현한다. 필요한 type은 소비 계약에서 가져오고 공개 API 변경은 통합자에게 전달한다. skip/상수 성공값/에러 삼키기로 assertion을 통과시키지 않는다.
- [ ] **S04 · GREEN 및 실패 경로.** 동일 test를 재실행하고 정상·취소·예산·I/O failure를 시험한다. `SC-005`와 표의 각 test에 source commit·binary SHA-256·command·exit code·stdout/stderr hash를 기록한다. 아직 없는 platform은 NOT_RUN으로 남긴다.
- [ ] **S05 · regression/scope.** 해당 group의 Debug/ReleaseSafe 시험과 dependencies의 영향받은 contract tests를 수행한다. tracked/untracked/rename/delete 경로가 소유 범위인지 검사한다. review 전에 memory lifetime과 error return을 다시 확인한다.
- [ ] **S06 · handoff.** `evidence/T16/handoff.json`에 base/head, contract digest, 변경 목록, export signature, test 결과, 제한·미통과 gate를 저장한다. 리뷰 가능한 전용 commit을 생성하되 통합자는 그 commit을 적용한 실제 integration binary로 다시 시험한다.
