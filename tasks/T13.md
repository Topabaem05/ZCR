# T13 · Immutable content·line cache Implementation Plan

**Goal:** Immutable content·line cache를 독립 검증 가능한 모듈과 증거로 완성한다.  
**Architecture:** [SDD](../docs/02-SDD.md)와 [공개 인터페이스](../docs/17-Data-Model-and-Interfaces.md)를 준수한다.  
**Tech Stack:** Zig 0.16.0, 승인된 public OS API.  
**Spec:** [구현 로드맵](../docs/13-Implementation-Roadmap.md), [테스트 계획](../docs/12-Performance-and-Test-Plan.md).  
**Dependencies:** T04, T10, T03  
**Status:** PENDING — 현재 실행 증거와 미완료 게이트는 [상태표](INDEX.md) 및 [progress.json](progress.json)을 따른다.

## 파일 소유권

아래는 향후 runtime repository에서 생성·수정할 경로다. ZIP에 구현됐다는 뜻이 아니다.

- `src/cache/content.zig`
- `src/cache/lines.zig`
- `src/cache/association.zig`
- Test: `tests/t13_test.zig`
- Evidence: `evidence/T13/` (사용자 source와 다른 task 경로는 금지)

공유 `build.zig`, `src/core/types.zig`, schemas는 통합자 소유다. 이 Task가 그 파일 소유자인 T01이 아닌 경우 export/contract 변경은 handoff로 요청한다. dependency의 파일을 몰래 수정해서 test를 통과시키지 않는다.

## 소비·생산 계약

**Consumes:** I13; ContentHash/FileVersion; I02 budget.  
**Produces:** cacheGet I13; second-touch cache and shared accounting.  
**금지/주의:** mtime+size만으로verifiedcontenthit를만들지않고path-only공유cache를만들지않는다.

## task-specific 구현 지침

content hash/domain과 mutable workspace association을 분리한다. 권한 확인 뒤 pin handle을 발급한다. sparse checkpoint는 128줄 간격부터 만들고 대형 grep의 첫 접근을 hot cache에 넣지 않는다. shared entry는 그룹에서 한 번 계산하며 pin된 객체를 evict하지 않는다.

## Step별 실행

- [ ] **S01 · scope preflight.** `task-t13` 전용 worktree에서 base/head와 dependency source/evidence hash를 고정한다. 허용 목록은 위 파일들+전용 tests/evidence뿐이다. dirty 사용자 변경이 있으면 보존하고 새 깨끗한 task worktree를 사용한다. source·build cache·TMP·test logs를 다른 task와 공유하지 않는다.
- [ ] **S02 · RED.** `tests/t13_test.zig`에 위 시나리오와 이 Task의 나머지 검증 행을 작성한다. 아래 명령을 실행하고 예상 기능이 없거나 올바른 assertion이 실패해서 RED인지 확인한다. unrelated compiler/toolchain 오류는 기능 RED 증거가 아니다.

```sh
zig build test -Dtest-group=memory -Doptimize=Debug
```

- [ ] **S03 · 최소 구현.** task-specific 구현 지침의 순서로 소유 모듈만 구현한다. 필요한 type은 소비 계약에서 가져오고 공개 API 변경은 통합자에게 전달한다. skip/상수 성공값/에러 삼키기로 assertion을 통과시키지 않는다.
- [ ] **S04 · GREEN 및 실패 경로.** 동일 test를 재실행하고 정상·취소·예산·I/O failure를 시험한다. `ME-004`와 표의 각 test에 source commit·binary SHA-256·command·exit code·stdout/stderr hash를 기록한다. 아직 없는 platform은 NOT_RUN으로 남긴다.
- [ ] **S05 · regression/scope.** 해당 group의 Debug/ReleaseSafe 시험과 dependencies의 영향받은 contract tests를 수행한다. tracked/untracked/rename/delete 경로가 소유 범위인지 검사한다. review 전에 memory lifetime과 error return을 다시 확인한다.
- [ ] **S06 · handoff.** `evidence/T13/handoff.json`에 base/head, contract digest, 변경 목록, export signature, test 결과, 제한·미통과 gate를 저장한다. 리뷰 가능한 전용 commit을 생성하되 통합자는 그 commit을 적용한 실제 integration binary로 다시 시험한다.

## 완료 게이트

전체 명시 test가 실행되어야 COMPLETE다. 경로 제한 위반, 요구 API와 다른 타입, lifecycle leak, 가짜 PASS, 실제 실행 없이 플랫폼 지원 표시는 REJECT다. 성능 실험이 포함되면 raw trace와 corpus/config digest를 남긴다. 다음 task는 말로 전달된 상태 대신 승인된 handoff를 읽고 시작한다.
