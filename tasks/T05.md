# T05 · Git-aware 탐색과 ignore Implementation Plan

**Goal:** Git-aware 탐색과 ignore를 독립 검증 가능한 모듈과 증거로 완성한다.  
**Architecture:** [SDD](../docs/02-SDD.md)와 [공개 인터페이스](../docs/17-Data-Model-and-Interfaces.md)를 준수한다.  
**Tech Stack:** Zig 0.16.0, 승인된 public OS API.  
**Spec:** [구현 로드맵](../docs/13-Implementation-Roadmap.md), [테스트 계획](../docs/12-Performance-and-Test-Plan.md).  
**Dependencies:** T02, T03  
**Status:** PLANNED — 구현·런타임 시험 미실행. 필수 Task.

## 파일 소유권

아래는 향후 runtime repository에서 생성·수정할 경로다. ZIP에 구현됐다는 뜻이 아니다.

- `src/fs/traverse.zig`
- `src/fs/ignore.zig`
- Test: `tests/t05_test.zig`
- Evidence: `evidence/T05/` (사용자 source와 다른 task 경로는 금지)

공유 `build.zig`, `src/core/types.zig`, schemas는 통합자 소유다. 이 Task가 그 파일 소유자인 T01이 아닌 경우 export/contract 변경은 handoff로 요청한다. dependency의 파일을 몰래 수정해서 test를 통과시키지 않는다.

## 소비·생산 계약

**Consumes:** I01/I02; FileSpec + Sink.  
**Produces:** enumerate I04; effective filters and coverage.  
**금지/주의:** unreadable/unsupportedfilename을빈성공으로숨기지않으며recurse thread를파일수만큼만들지않는다.

## task-specific 구현 지침

ignore stack과 streaming directory walk를 구현한다. parent negation 제약, escape pattern, hidden-file policy를 분리한다. 200,000개 파일에서 path cache 상한을 넘으면 streaming으로 내려간다. 정렬 결과와 discovery 순서의 의미를 구분한다.

## 검증 시나리오

| ID | Given | When | Then / 합격 조건 |
|---|---|---|---|
| FS-001 | nested .gitignore와 negation | 파일 나열 | Git 규칙 oracle과 effective policy 내 동일 file set |
| FS-002 | ignored parent 아래 reinclude child | 나열 | parent 제외 제약 유지 |
| FS-003 | hidden/.git/escaped # !/space 패턴 | 나열 | policy 정확 적용, .git write scope 없음 |
| FS-004 | 200k-file corpus와 작은 path cap | streaming traversal | 전체 index 할당 없이 bounded memory와 coverage 유지 |
| FS-005 | symlink loop·unreadable directory | 나열 | loop 없음, unreadable 때문에 complete=false |
| FS-006 | valid Unicode와 non-UTF8 path | 나열 | 문자 손실 없음, 미지원 이름 누락을 coverage에 표시 |

첫 RED test는 다음 명시적 동작을 assertion으로 만든다. 이것은 구현자가 실행 시험으로 옮길 **test specification**이며 현재 실행한 결과가 아니다.

```json
{
  "id": "FS-001",
  "given": "nested .gitignore와 negation",
  "when": "파일 나열",
  "then": "Git 규칙 oracle과 effective policy 내 동일 file set"
}
```

## Step별 실행

- [ ] **S01 · scope preflight.** `task-t05` 전용 worktree에서 base/head와 dependency source/evidence hash를 고정한다. 허용 목록은 위 파일들+전용 tests/evidence뿐이다. dirty 사용자 변경이 있으면 보존하고 새 깨끗한 task worktree를 사용한다. source·build cache·TMP·test logs를 다른 task와 공유하지 않는다.
- [ ] **S02 · RED.** `tests/t05_test.zig`에 위 시나리오와 이 Task의 나머지 검증 행을 작성한다. 아래 명령을 실행하고 예상 기능이 없거나 올바른 assertion이 실패해서 RED인지 확인한다. unrelated compiler/toolchain 오류는 기능 RED 증거가 아니다.

```sh
zig build test -Dtest-group=fs -Doptimize=Debug
```

- [ ] **S03 · 최소 구현.** task-specific 구현 지침의 순서로 소유 모듈만 구현한다. 필요한 type은 소비 계약에서 가져오고 공개 API 변경은 통합자에게 전달한다. skip/상수 성공값/에러 삼키기로 assertion을 통과시키지 않는다.
- [ ] **S04 · GREEN 및 실패 경로.** 동일 test를 재실행하고 정상·취소·예산·I/O failure를 시험한다. `FS-001`와 표의 각 test에 source commit·binary SHA-256·command·exit code·stdout/stderr hash를 기록한다. 아직 없는 platform은 NOT_RUN으로 남긴다.
- [ ] **S05 · regression/scope.** 해당 group의 Debug/ReleaseSafe 시험과 dependencies의 영향받은 contract tests를 수행한다. tracked/untracked/rename/delete 경로가 소유 범위인지 검사한다. review 전에 memory lifetime과 error return을 다시 확인한다.
- [ ] **S06 · handoff.** `evidence/T05/handoff.json`에 base/head, contract digest, 변경 목록, export signature, test 결과, 제한·미통과 gate를 저장한다. 리뷰 가능한 전용 commit을 생성하되 통합자는 그 commit을 적용한 실제 integration binary로 다시 시험한다.

## 완료 게이트

전체 명시 test가 실행되어야 COMPLETE다. 경로 제한 위반, 요구 API와 다른 타입, lifecycle leak, 가짜 PASS, 실제 실행 없이 플랫폼 지원 표시는 REJECT다. 성능 실험이 포함되면 raw trace와 corpus/config digest를 남긴다. 다음 task는 말로 전달된 상태 대신 승인된 handoff를 읽고 시작한다.
