## Original findings (resolved by c926ea9)

1. **[P1] Sample expiry clocks at the serialized authority check, after acquiring the registry mutex.** `src/workspace/registry.zig:324–330` reads monotonic and wall time before waiting for the mutex in `renewWriter`. The same pattern occurs in `validateSession` (246–250), `acquireWriter` (285–296), `validateLease` (314–320), `beginCallback` (340–346), and `validateCallback` (350–359); `bindSession` also checks wall expiry before taking its lock (217–222). For example, a renewal/commit check samples time just before a 30-second expiry, is delayed before or while acquiring the mutex, and then passes that earlier timestamp to `State` after expiry. If no other call observed expiry, an expired lease can be renewed, or the pre-publication callback check can succeed using a stale timestamp; task/session expiry has the same problem. Read the clocks inside the critical section immediately before evaluating authority (clock reads do not perform the filesystem/subprocess I/O forbidden by INV-05). Add a deterministic clock/mutex delay regression that crosses expiry between entry into the operation and its serialized state check. The existing pure `State` tests always provide the intended current time and do not exercise this registry integration boundary.

2. **[P2] Revoke only the writer owned by the disconnected or expired task.** `src/workspace/registry.zig:260` unconditionally revokes the workspace writer when any bound session disconnects. `authorizeTask` (277–279) and `checkLeaseBinding` (303–305) do likewise for an expired task. With A and B legitimately bound to the same workspace, B can own its writer and callback while A is only reading; disconnecting A cancels B and invalidates B's callback. An expired acquire from A, or validation/renewal of A's old lease after B has become writer, has the same effect. `checkLeaseBinding` performs this revocation before the lease state verifies the supplied lease against the current owner/fence. Scope these revocations to `currentLease().task_id == affected_task_id`; keep workspace-wide revocation for workspace retirement, explicit revoke, and managed-write disable. Add a two-task regression proving that A disconnect/expiry/stale lease leaves B's writer and callback valid, while disconnecting or expiring B still revokes it.

## Accepted design and integration requirements

- I08/I09 signatures conform to the frozen core declarations. Required supplemental `validateSession(session, current_boot)` / `validateWorkspace` checks before static Authorizer use are accepted as instructed; their integration remains mandatory.
- Real Git discovery uses explicit argv, an isolated environment, bounded output/time, exact canonical root matching, and retained root/per-worktree/common-directory handles. Workspace IDs are registry UUID plus fresh incarnation; common repository identity remains separate from per-worktree identity. Retained `.git` marker identity/hash and path/handle validation detect the tested delete/recreate, move, and linked-marker replacement scenarios.
- Registry state is bounded at 32 lifetime incarnations, 16 sessions, two discoveries, and 64 callbacks per workspace. Retired entries remain address-stable, keep handles, invalidate bindings/fences, and prevent replacement writers until callbacks drain. The explicit drain-and-restart response to lifetime capacity exhaustion is documented.
- The pure lease state correctly checks exact owner/workspace/fence/expiry snapshots, uses 30-second TTL and 10-second renew interval, preserves callback tickets across renewals, rejects stale/double/foreign tickets, and refuses counter overflow. Independent lease subreview found no drain bypass in `State` under its documented serialization and current-time preconditions.
- Filesystem validation, Git process work, secure randomness, and policy allocation occur outside the registry mutex. Exclusive deinit preserves storage when callbacks or discovery remain live.
- Managed writing requires an explicit host assertion; shared editor mode cannot acquire a writer. Publication still must serialize callback validation with cancellation in its workspace actor. This module does not itself provide a filesystem compare-and-swap operation.
- Watchers must call `markChanged` for dirty-file mutations. A rediscovered changed HEAD increments generation. Native macOS/Windows and actual host integration remain explicitly NOT_RUN.
